# Failure analysis

Source run: `eval\results\baseline.json`. Rows judged `WRONG` or `PARTIAL`, incorrect refusals, and explicit service/judge failures are classified. Diagnostic labels are provisional; generation-format failures are grouped under wrong synthesis. Classified failures: **155**.

Completed production arms are included below; reused default-anchor rows are excluded to avoid counting the same observation twice. Baseline judge v1 and subsequent judge v2 are distinct protocols; these diagnostic counts are not pooled quality estimates.

| Category | Count | Proposed fix |
|---|---:|---|
| Service/Generation Availability | 6 | Bound network timeouts and retry transient service failures; do not tune retrieval thresholds to fix an outage. |
| Judge Unavailable | 2 | Retry grading the same saved answer when the judge recovers and always show judged coverage; do not omit failures from the denominator silently. |
| Retrieval Miss | 0 | Inspect query rewriting and hybrid retrieval; add source-aware lexical signals and tune the threshold using held-out questions. |
| Chunk Split | 2 | Increase overlap or add structure-aware/heading-aware chunking so the evidence needed for one answer remains in a retrievable chunk. |
| Wrong Synthesis | 125 | Extract final non-thought text, allow a sufficient output budget, validate JSON and reject SDK dumps/truncated output; then verify each claim against passages. |
| Bad Refusal Threshold | 20 | Calibrate false and missed refusals on a separate holdout. The no-RAG evidence-only prompt requires a separate control; threshold tuning cannot fix that confound. |
